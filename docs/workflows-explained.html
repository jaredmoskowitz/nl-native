Workflows,
made real.

Anthropic draws one line: a workflow orchestrates models through code paths you design; an agent directs itself. NL Native is already a workflow — it just needs two of its own patterns turned from promise into mechanism.

scroll ↓
predefined

Workflow

LLMs and tools orchestrated through predefined code paths. You decide the steps; the model fills the thinking. Predictable, repeatable, cheap to debug.

emergent

Agent

The model directs its own process — choosing tools and order dynamically. Flexible, but harder to predict and more expensive to run.

→ The article's one rule: start simple. Reach for a workflow when the task has structure you already understand.

The vocabulary

Five workflow patterns

From a fixed line, to a fork, to a fan-out, to dynamic delegation, to a feedback loop. The last two start blending toward agent territory.

01

Prompt chaining

Fixed sequential steps; each step eats the previous output.

USE WHEN → task decomposes cleanly; trade latency for accuracy.
02

Routing

Classify the input, then send it to a specialised handler.

USE WHEN → distinct categories handled better apart.
03

Parallelization

Run calls at once — sectioning (split) or voting (repeat & compare).

USE WHEN → pieces are independent, or you want multiple takes.
04

Orchestrator–workers

A central model breaks the task apart on the fly and delegates.

USE WHEN → subtasks can't be known up front. ↗ leans agentic
05

Evaluator–optimizer

One model generates, another critiques, loop until good.

USE WHEN → clear criteria exist; refinement measurably helps. ↗ leans agentic

What to learn

Three lessons

1

Your parallelism is asserted, not enforced

fan-out.md says "launch agents simultaneously." But it's prose one Claude reads top-to-bottom — no Task tool, no subagent spawn. One context role-plays all three roles in sequence.

The danger isn't speed. Your whole hub-and-spoke topology rests on "platform agents never communicate." When one context becomes iOS, then Android, it already holds every iOS decision the moment it "becomes" Android. The exact contamination the design exists to prevent is structurally guaranteed.

sectioning only pays off if sections are truly isolated
2

...but don't just port it to parallel()

The obvious fix — spawn three real subagents — kills your cleverest feature. Contract-version monitoring (fan-out.md:119) needs a live agent to halt mid-task, re-read a bumped contract, and resume. Isolated subagents can't be tapped on the shoulder mid-run.

So the irony: the "fake" serial parallelism is exactly what makes mid-flight contract sync possible. Going truly parallel forces a redesign — barrier-synced milestones, where the Architect re-syncs between rounds instead of continuously. That tension is the real design conversation.

the constraint that makes it hard & interesting
3

/verify is an evaluator, not an evaluator-optimizer

QA Verifier "reports findings only — never fixes," and BLOCKERs just halt. That's half the pattern. Close the loop: verify → route each finding to the owning platform agent → fix → re-verify → until clean. QA still never fixes; it just triggers the owner.

clean win — clear criteria already exist

Zoom in

Inside one barrier

When all three finish a milestone, they pause. Only the Architect runs the reconcile.

Collect

Each platform reports what it built + any constraint reports or contract gaps it discovered (e.g. "iOS needs a createdAt the contract doesn't define").

Decide

The Architect — and only the Architect — decides whether to bump any contract. This is now the one place a version changes. Deterministic, not "whenever."

Freeze

The new contract version is frozen for the entire next milestone. No agent has to watch for mid-flight bumps anymore.

Release

Each platform gets a fresh context seeded with exactly two things: the frozen contract and its own prior output — never the other platforms' internals. The contract becomes the only channel. That's your hub-and-spoke diagram, finally enforced.

Concretely

The shape in the Workflow tool

Not pipeline() — pipeline has no barrier between stages, and we need one. It's parallel() per milestone with an Architect reconcile between rounds.

let contract = frozenInitialContract              // from gate-review
let priorOutput = { ios: null, android: null, backend: null }

for (const milestone of ['data-layer', 'primary-screens', 'polish']) {

  // ── BARRIER: three lanes, isolated worktrees, frozen contract ──
  const built = await parallel([
    () => agent(iosPrompt(milestone, contract, priorOutput.ios),     { isolation: 'worktree', schema: PLATFORM_OUT }),
    () => agent(androidPrompt(milestone, contract, priorOutput.android),{ isolation: 'worktree', schema: PLATFORM_OUT }),
    () => agent(backendPrompt(milestone, contract, priorOutput.backend),{ isolation: 'worktree', schema: PLATFORM_OUT }),
  ])

  // ── the ONLY place contracts change ──
  const reconcile = await agent(architectPrompt(built, contract), { schema: RECONCILE_OUT })
  contract    = reconcile.frozenContract              // bump happens here, or not
  priorOutput = { ios: built[0], android: built[1], backend: built[2] }

  if (reconcile.blockers.length) { /* surface to human gate */ }
}

This is the textbook legitimate barrier: the next milestone needs cross-platform context — all three reports — before the Architect can freeze. worktree isolation lets three agents write platforms/{ios,android,backend} at once without collision.

Honest accounting

The trade-off

You gain

  • Real isolation — the guarantee becomes true
  • Determinism — contracts change at known points
  • Genuine wall-clock parallelism

You lose

  • Instant reaction to a contract gap
  • A gap found early waits up to one milestone to resolve

For coherence-critical work, that trade is correct. Drift is the expensive failure; a milestone of latency is cheap.

First, partition — not every finding loops

Implementation-class → loops

Routes to a platform or Backend expert. A concrete fix exists; the agent applies it in its own worktree, QA re-verifies just that finding.

missing test coverage
unhandled error code
interaction state not represented
mock→real mismatch

Decision-class → escalates at once

Routes to Architect (contract), Spec Analyst (ambiguity), or UX Designer (behavioral). These need a decision, not a fix — auto-looping would invent intent.

spec ambiguity
contract version mismatch
missing / unclear requirement
cross-platform behavioral disagreement

What changes in verify.md

Was — human is the loop

verify.md:101 — "If any BLOCKER exists, stop here. Route findings and wait for fixes."

verify.md:206 — "After fixes, the user should re-run /verify."

Every round is a manual round-trip. Nothing closes itself.

Now — orchestration is the loop

Partition findings into implementation vs decision class.

Implementation BLOCKERs enter a bounded auto-loop (≤ 2 rounds): route → fix in worktree → re-verify that finding.

Decision-class findings escalate to the human immediately. Survivors after round 2 escalate too.

On clean → one full Phase A sweep → Phase B. Human gate stays at /propose.

The orchestration shape

// Phase A — parallel per-platform verification
const reports = await parallel([
  () => agent(verifyPrompt('ios', specs),     { schema: PHASE_A_OUT }),
  () => agent(verifyPrompt('android', specs), { schema: PHASE_A_OUT }),
  () => agent(verifyPrompt('backend', specs), { schema: PHASE_A_OUT }),
])

// partition — the finding already names its route
let open    = reports.flatMap(r => r.findings).filter(f => f.severity === 'BLOCKER')
const decide = open.filter(f => ['Architect','Spec Analyst','UX Designer'].includes(f.route))
let remaining = open.filter(f => /Expert$/.test(f.route))   // platform + integration

if (decide.length) escalateToHuman(decide)                  // need a decision, not a fix

// the bounded loop — default (d): 2 rounds, then escalate
let round = 0
while (remaining.length && round < 2) {
  round++
  await parallel(byPlatform(remaining).map(([platform, findings]) => () =>
    agent(fixPrompt(platform, findings), { isolation: 'worktree' })   // expert fixes; QA never does
  ))
  const verdict = await agent(reverifyPrompt(remaining), { schema: VERDICT })  // re-verify ONLY these
  remaining = remaining.filter(f => !verdict.resolved.includes(f.id))
}

if (remaining.length) escalateToHuman(remaining)            // survivors → default (e)

// default (f): one full sweep catches regressions, then Phase B
const sweep = await agent(fullPhaseAPrompt(), { schema: PHASE_A_OUT })
if (sweep.clean) runPhaseB()

Note the symmetry with the barrier fan-out: fixes happen in each platform's worktree (git Option B), so a verify-loop fix is just re-entering that platform's isolated branch — the two designs compose. QA's "reports only" rule (qa-verifier.md:5) is untouched: it produces findings and re-verification verdicts; the orchestration routes; the platform expert is the only one who edits code.
